# Analyst programme, analyst event and large brand programmes

Every figure is a field ("[User to add: ...]"). The skill never names an analyst firm, a report or a ranking the user did not name, and never promises a placement.

## A. Analyst programme (a programme, not an event)

**When to choose it:** influencers in the buying process, when the company's value proposition per segment is already clear.

**Method:**
- Present the offering in a structured way to the analysts who track each buyer persona, plus industry bodies, researchers and technology reporters reached through PR.
- Deliverables: early briefings; every relevant analyst covered at a cadence the user sets [User to add]; speaking opportunities at industry events through the PR team.
- Results to plan for: analyst mentions, and a joint case study or report with an analyst, over a horizon the user sets [User to add].

**Before starting (enablement):** the value proposition for each segment must be clear first. Senior leadership time with analysts is required [User to add: whose time and how much]. Inclusion in a major analyst report is not a quick outcome; some recognition options carry extra charges; the skill states no timeline and no price.

**Effort and budget:** effort per week [User to add]; budget lines for analyst firms and research reports, amounts [User to add].

**What to measure (fields):** analysts briefed, mentions, inclusion in reports, joint content, speaking slots secured [User to add].

**Common mistakes:** briefing before the value proposition is clear; no leadership time; expecting a placement on a timeline the firm has not confirmed.

**Hand offs:** press releases and announcements to pr-launch-pack.

**What the skill does now:**
1. Purpose and stage: analysts are influencers, not leads, so the event is planned against the influencer row of the funnel stage map (choice-method.md section 3), not against a lead target. The goal of the event is the user's [User to add: what the event should achieve].
2. Choice: compare an analyst event with the other options the user is weighing using the single bet comparison table (choice-method.md section 1), with the rows read for analysts (what do we get, credibility in the market, list match with the analysts the user wants to reach [User to add], package cost).
3. Timeline: the shared pre, during and post timeline (shared-process.md section 4), with suggested defaults the user decides on; one owner per analyst (shared-process.md section 6).
4. Measures: fields the user sets [User to add: measures for the event]. If the event sits inside an analyst programme, section A describes that programme; it is not the method for the event.

**Not yet in the method (the skill asks for the user's material and does not invent it):** an analyst event agenda or run of show, an invite list method, a briefing pack format, the rules for embargoed material, and measures specific to an analyst event.

## C. A programme of several event types for a large brand (method being completed)

Method being completed. A fuller programme template for large brands is not yet in the method. This section is built only from the shared process and the choice method, and the skill does not guess event types beyond those it covers.

**What the skill does now:**
1. Plan backwards from the brand's targets by region and segment (shared-process.md section 1).
2. One portfolio table row per event type the user names, with funnel economics by script. The types this skill has a method for are roundtable, exhibition, webinar, podcast, event visit, summit sponsorship, panel moderation, AMA or LinkedIn Live, workshop, partner and customer events, and analyst programme. A type the user names that is not on that list (for example a launch event, a dealer meet or an offsite) still gets its row, with every value a field and the line "not yet in the method"; it is never dropped silently and never planned from guesswork.
3. Allocation by funnel stage, company segment, plan phase, budget and season (choice-method.md sections 3 to 8).
4. The shared timeline and core group per event, one owner per contact across the whole programme, so that two teams never write to the same person.

**Not yet in the method:** the full list of event types a large brand programme uses, their sequence across the year, governance across regions and brands, and budget templates. Ask the user for their own programme document.
