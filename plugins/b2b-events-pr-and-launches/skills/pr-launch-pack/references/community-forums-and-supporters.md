# Community forum posts and supporters

## A. Community forum posts (launch sites, discussion forums, user communities)
1. Study first. Before writing, read real threads in each forum: launches or posts like this one, what got traction and what was ignored, the tone, the length, the rules. With web access, open the forum's own pages; without it, ask the user to paste two or three real threads. Never write from an assumed forum style.
2. Read the forum's current rules and limits (title length, description length, links, self promotion rules) from the forum's own pages or the user. Never state a limit from memory as fact. Test the text in the forum's own submission form if the user can.
3. One post per forum. Each written for that forum's readers and rules. Never the same text in two forums.
4. Real numbers and screenshots only. Every figure in a forum post is in the claims register as verified or confirmed. Screenshots must be real and checked for personal data (names, emails, file paths, internal URLs) before posting.
5. The user posts first. Teammates who join the thread align to what the user posted and add their own view in their own words.
6. Answer questions in the thread truthfully, including what the product does not do.

## B. Supporters
- Supporters (colleagues, customers, partners, friends) get labelled talking points, never scripted comments.
- A talking points sheet: the launch in one sentence, three facts they may mention (verified), what not to say (unverified claims, prices not yet public), and a note that they should write in their own words only if they want to.
- Never write comments for people to post as if they were their own, never write persona comments, and never suggest posting from accounts that are not real people.
- If the user asks for "sample comments people can post", explain this rule in one line and give the talking points instead.

## C. Platform respect
Follow each platform's guidelines on self promotion, links and coordinated activity. If a plan would break a platform's rule, say which rule and offer a version that does not.
